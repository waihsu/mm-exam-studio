# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities in a public issue, discussion, pull request, screenshot, or chat transcript. Use the repository's private security-advisory channel when it is enabled, or contact the project maintainer through the private contact listed in the repository settings.

Include a clear description, affected component, reproducible steps, likely impact, and any suggested mitigation. Do not include secrets, real learner data, or production tokens.

Maintainers should acknowledge reports promptly, investigate privately, and coordinate a fix before public disclosure.

## Scope

Reports are especially welcome for authentication, authorization, session handling, rate limiting, database access, file handling, PDF generation, mobile secure storage, and deployment configuration.

## Before public release

The repository owner must configure a real private security contact or GitHub security-advisory channel. This file deliberately does not publish an unverified email address.
